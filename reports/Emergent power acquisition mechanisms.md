# Source Gates the Pool; Method Picks the Fill

Four genres that have already solved "generate a distinctive effect without a lookup table and without an open pool" converge on the same two-part architecture, and it maps directly onto Pattern P5's own language: **the source of an ability (the monster's nature, the manufacturer, the god) does not add a stat or get searched in a flat table — it categorically gates which small, bounded sub-pool of behavior-templates is even eligible**, and **the acquisition method (how it was defeated, which currency rolled it, which prerequisite boons are held) then determines the *selection mechanism* used to fill a slot from that gated pool** — guaranteed pick, weighted roll, deterministic craft, or biased reroll. Diablo's Unique/Legendary items, Borderlands' manufacturer-locked part pools, and Path of Exile's tag-matched mod-weighting all independently arrived at this same split between a small hand-authored "identity" layer and a large systematic "magnitude" layer that never compete for the same output slot. For the second flavor of P5 — class-emerging-from-aggregate-history — the LitRPG genre's most mechanically explicit implementation (the serial *Delve*) uses a directly transferable dual-tier threshold: a **Primary Requirement** (a rank-count or ratio across a small, fixed set of playstyle categories) gates eligibility, and a **Secondary Requirement** (a cumulative action counter — kills, mana spent, damage mitigated) determines when the gated class actually triggers, with the load-bearing trick — confirmed independently by Hades' Duo Boon system in the roguelike research — being that the threshold table is keyed off a small, fixed number of *category axes*, never off the full, ever-growing list of individual abilities or monsters. On the lighter side-question, no surveyed narrative TTRPG or LLM-GM project tracks a grid, and the one documented case of an LLM attempting freeform spatial reasoning without any structured backstop (ChatRPG) produced narrated self-injuries and wrong-target attacks — the fix that worked was a small enumerated relationship state (engaged/at-range/flanked, in the shape of Ironsworn's close-quarters-vs-range binary or Blades in the Dark's Position axis) resolved through a structured tool call, not a visual grid and not unconstrained prose. Together these findings give Pattern P5 something it has lacked since it was flagged "Open Design Priority": two concrete, differently-shaped candidate mechanisms, one per flavor, plus a companion answer for spatial adjudication that fits this project's existing three-layer AI-GM architecture without requiring a grid.

## Diablo, Path of Exile, and Borderlands all split "identity" from "magnitude" into non-competing layers

The clearest architectural finding in this round's research is that no ARPG asks a single random-roll table to produce both a signature identity and generic magnitude. Diablo II's Unique and Set items are a wholly separate data structure from its Magic/Rare items: their three-to-eight properties were "custom created by Blizzard North" rather than drawn from the shared prefix/suffix tables, and critically, "there are no rules to the mods that can be on a unique, unlike with magical and rare items" ([PureDiablo: Unique Items](https://www.purediablo.com/diablo-2/uniques)). Diablo III's Loot 2.0 rework enforced the same separation structurally rather than just narratively: a Legendary Power is placed in a reserved Secondary-affix slot "specifically so it never competes with an item's Primary stat roll" ([Diablo Wiki: Legendary Affixes](https://www.diablowiki.net/Legendary_Affixes)) — composition by slot reservation, not by table competition. Diablo IV's Tempering system is the most directly relevant precedent for P5's "how it was acquired" half: a player finds a Temper Manual (a small, hand-authored, world-dropped recipe containing three-to-five possible affixes categorized by theme, e.g. "Mobility"), and *applying* that recipe to a specific item still randomizes which of the three-to-five affixes lands and at what roll value — three independently-tuned layers (a found category, a constrained random fill, and a numeric roll) stacked on top of each other rather than one undifferentiated table ([Maxroll: Tempering Guide](https://maxroll.gg/d4/resources/tempering-guide)). Notably, Diablo III's own launch-era itemization was a design failure specifically because it let rare/legendary stats roll in a "completely random," unconstrained way for nearly two years before Loot 2.0's structure fixed it — a directly citable case of a genre-defining studio treating full openness as a bug, not a feature, and correcting toward more structure ([DiabloFans: Every Legendary Affix So Far](https://www.diablofans.com/forums/read-only-diablo-forums/diablo-iii-general-discussion/77294-every-legendary-affix-so-far)).

Path of Exile makes the "source gates a bounded sub-pool" mechanism completely explicit at the algorithm level. Every mod carries a domain and a list of tags it can spawn on with a weight per tag; the base item carries its own tags, and "the generator collects all tags on the item, sums the matching weights across the mod pool, and discards any mod whose total weight resolves to zero for that item" — a hard eligibility filter layered under a soft probability weighting ([vhpg.com: Spawn Weighting PoE](https://www.vhpg.com/spawn-weighting-poe/)). A **mod group** rule then enforces hard mutual exclusivity so that, for instance, two different tiers of the same "% increased life" mod can never both land on one item ([PoE Official Forum: Understanding Mod Groups](https://www.pathofexile.com/forum/view-thread/3587391)) — and every item, regardless of how large the underlying mod table grows, is hard-capped at three prefixes and three suffixes, meaning PoE solves combinatorial legibility not by shrinking the total design space but by **bounding the number of simultaneously-active rolled slots per object** ([mmoso.com: PoE2 Currency Guide](https://www.mmoso.com/news/comprehensive-guide-to-path-of-exile-2-currency-system)). Currency items are then just different *entry points* into that same weighted table rather than separate generators: Essence guarantees one specific affix while the rest still rolls normally, Fossils bias the weighting toward a theme, and the Crafting Bench deterministically adds one chosen mod to an open slot ([Path of Exile Wiki: Essence](https://pathofexile.fandom.com/wiki/Essence); [rpgstash.com: PoE Crafting Guide](https://www.rpgstash.com/blog/how-to-craft-every-item-in-path-of-exile)) — which is precisely the "acquisition method selects the fill mechanism" half of the pattern this report proposes for P5. Borderlands supplies the cleanest illustration of "source" as a categorical gate rather than a flavor tag: manufacturer identity does not modify a shared parts pool, it *replaces* which pool is even eligible — Tediore guns are reload-by-throwing-and-detonating, Maliwan guns are elemental-only, Jakobs guns are never elemental but trade that away for high critical multipliers, and these are described as expressing each brand's in-fiction values "through mechanics, not just flavor text" ([gamerant.com: How Borderlands' Guns Reflect Their Manufacturers' Values](https://gamerant.com/borderlands-guns-symbolism-manufacturer-values-beliefs-style-tediore-dahl-jakobs/)). Borderlands 3 tightened this further by eliminating cross-manufacturer part-mixing entirely — "each manufacturer has multiple variants for each part of a given type of weapon" rather than a shared universal part pool — because the earlier, more combinatorially open version was judged less legible and less brand-coherent, the same correction-toward-structure arc Diablo III went through with Loot 2.0 ([Borderlands Fandom Wiki: Borderlands 3 Weapons](https://borderlands.fandom.com/wiki/Borderlands_3_Weapons)).

## Slot-claiming effects need a priority rank, not a pairwise table — Isaac already proved it and PoE already justified adopting it

Binding of Isaac is the one case study in this round that shows where the "gate a pool, then roll" pattern *breaks*, and the breakage matters directly for P5's slot-claiming abilities (an acquired power that overrides a basic attack, not one that merely adds a number). The great majority of Isaac's 700+ item interactions emerge for free because ordinary stat-modifying passives all write into a shared `MC_EVALUATE_CACHE` recalculation pass — "the callback runs right after a stat evaluation happens," and items add modifiers to that shared cache rather than needing to know about each other ([Binding of Isaac: Rebirth Lua API Docs](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html)). But the game's *most famous, build-defining* synergies are the tear-replacer items (Brimstone, Mom's Knife, Technology, Haemolacria, the Ludovico Technique), which compete for exclusive control of "what does the attack look like," and for exactly this category the wiki documents explicit, hand-specified priority for every conflicting pair — "Mom's Knife has priority" over Brimstone, "Haemolacria has priority" over Brimstone, and so on down the list (community synergy summary compiled from the Binding of Isaac: Rebirth Wiki's Brimstone, Haemolacria, Technology, and Mom's Knife pages). The lesson generalizes cleanly: a shared pipeline scales for additive, stacking effects, but mutually-exclusive slot-claiming effects reintroduce an O(n²) hand-authoring problem, and the fix that actually shipped was not a full pairwise table but a **rank-ordered priority field per effect** — O(n) authoring, one number per effect, rather than one rule per pair. This is exactly the same shape as the mechanism this project's constitution already adopted from Path of Exile's own priority-ordered projectile tags (Pierce beats Fork beats Chain beats Return) as a companion to Pattern P6, and this round's research shows the identical primitive independently reinvented by Isaac's designers for a different genre and a different problem — strong convergent evidence that a priority-rank field, not a bespoke pairwise table, is the right general-purpose answer whenever an acquired-ability system lets two abilities compete for the same behavioral slot.

Risk of Rain 2 supplies the cleanest counter-case for effects that are *additive and probabilistic* rather than slot-claiming, and it is arguably the strongest single mechanism in this round's research for avoiding pairwise authoring altogether. Every on-hit item independently rolls its own trigger chance, scaled by a single shared **proc coefficient** attached to whatever attack landed the hit — "Effective Trigger Chance = Item Chance × Proc Coefficient" ([Risk of Rain 2 Wiki: Proc Coefficient](https://riskofrain2.wiki.gg/wiki/Proc_Coefficient)) — and stacking uses one of only two shared formula families (linear or hyperbolic) across the entire item pool rather than bespoke per-item curves, with damage-over-time effects fixed at a proc coefficient of 0.0 specifically to prevent infinite proc chains as one global rule rather than a hand-authored exception per pair ([GameRant: How Do Proc Coefficients Work In Risk Of Rain 2?](https://gamerant.com/risk-of-rain-2-ror-2-proc-chain-coefficients-explained/)). No priority/ordering system for simultaneous procs exists at all — a new on-hit item just needs a trigger-chance number, and it composes correctly with every existing item and every character's coefficient with zero additional authoring, reducing an O(n²) problem to O(n) (one number per item) plus O(1) (one shared formula). Slay the Spire runs the same architecture at the level of card/relic design: cards and relics are independently-authored objects subscribing to a small, shared set of combat event hooks (`OnCardUse`, `OnPlayerDamaged`, `OnPowersModified`, and similar callbacks documented in the BaseMod modding framework), so synergy is discovered, not authored — Mega Crit's own lead designer described using play telemetry, not a hand-designed combination catalog, to find and rebalance emergent interactions after the fact ([GDC Vault: 'Slay the Spire': Metrics Driven Design and Balance](https://www.gdcvault.com/play/1025731/-Slay-the-Spire-Metrics)). Hades is the one deliberate exception that proves the rule about scale: its ~30 Duo Boons are a sparse, hand-curated table, but the table is keyed off the **god pairing** (a low-cardinality dimension — C(8,2) = 28 possible pairs in Hades I, and Hades II's 37 duo boons against C(9,2) = 36 possible pairs shows the same ratio held even as the roster grew), never off the much larger and ever-growing set of individual boons ([Hades Duo Boons data tool](https://orlp.github.io/hades-boons/duo_boons.html); [RogueRanker: Hades 2 Duo Boons](https://rogueranker.com/hades-2-duo-boons/)). A hand-curated table is survivable exactly when it is keyed off a dimension the design team controls the size of — a finding that transfers directly to P5's class-from-history question below.

## Delve's dual-tier threshold is the one LitRPG mechanism explicit enough to implement directly

Five RoyalRoad/published LitRPG series implement some version of class-from-aggregate-history, and they split into three structurally distinct sub-patterns that this report keeps separate rather than treating as one genre convention. *Delve* is the only series whose mechanism is close to an implementable game rule as originally written: hidden classes unlock via a **Primary Requirement** — a rank-count within a named skill category (e.g., "at least 4 skills at or above rank 5" in Offensive Auras) or a stat ratio (Clarity at least 5 times Focus for the Dynamo class) — combined with a **Secondary Requirement**, a cumulative action counter such as kills scored using a specific mechanic (at least 50 kills via Offensive Auras) or cumulative mana spent (at least 5,000 mana through Aura Metamagic for the Meta-Beacon class), with even higher tiers ("Legendary Dynamo") gated on extreme cumulative totals like 1,000,000 total mana recovered ([Delve Wiki: Class](https://bestspellever.fandom.com/wiki/Class); [Delve, "052: Specialization"](https://www.royalroad.com/fiction/25225/delve/chapter/412697/052-specialization)). This reads as deterministic and transparent *once unlocked* — the system surfaces the option by name with the qualifying numbers implied — but opaque *in advance*, since a character doesn't know a hidden class exists until its thresholds are already close to met ([Delve, "012: Class"](https://www.royalroad.com/fiction/25225/delve/chapter/369623/012-class)). Crucially, Delve's category axes (Offensive Auras, Defensive Auras, Aura Metamagic, a Clarity/Focus ratio) are a small, fixed, author-controlled set — the same low-cardinality-keying trick Hades uses for its Duo Boon table — which is what keeps the threshold table tractable even as the number of individual skills a character can hold grows without bound.

*The Wandering Inn* and *Defiance of the Fall* implement the same underlying idea — the system tracks a character's history and issues a class off of it — but keep the mechanism narratively opaque rather than numeric: Erin Solstice earns the Innkeeper class after a sustained pattern of actually running an inn, and class re-evaluation "usually happens at ten-level intervals," with off-schedule "off-classes" as an exception for sufficiently dramatic shifts ([Wandering Inn Wiki: Classes](https://wiki.wanderinginn.com/Classes)); Defiance of the Fall grants a character's first class at level 25, "mainly based on achievements and experiences," with no visible formula or counter ever shown on the page ([Defiance of the Fall Wiki: Known Classes](https://defiance-of-the-fall.fandom.com/wiki/Known_Classes)). *Threadbare*'s protagonist instead accumulates a large roster of separate classes (Tailor, Duelist, Necromancer, Golemist, and others) through repeated task-specific actions, implying one counter per candidate class rather than a single blended axis. The genre's clearest answer to "what happens when history is genuinely mixed" comes from Wandering Inn's **consolidation** mechanic: two sufficiently-advanced classes can merge into a new named hybrid — [Warrior] and [Strategist] can merge into [Commander], and one character's [Princess], [Warrior], [Barmaid], [Beast Tamer], [Carer], and [Tactician] classes consolidated into the single title [Worldly Princess] — described as requiring a secondary class to be advanced "sufficiently to inform" the primary one, a plurality-based merge rather than a stated 50/50 tie-break rule ([Wandering Inn Wiki: Classes](https://wiki.wanderinginn.com/Classes)). No source across any of the five series states an explicit numeric tie-breaking formula for exactly when two competing histories mint a hybrid versus a single winner — this is a genuine, unresolved gap in the genre's own prior art, not merely an omission in this research pass, and any adopting spec should treat "the hybrid-merge trigger rule" as original design work rather than an importable formula.

## A structured relationship-state, not a grid, is the genre-wide answer to prose-only tactical combat

Every narrative-first TTRPG surveyed in this pass — Blades in the Dark, Fate Core, Dungeon World, Ironsworn/Starforged, Mörk Borg — resolves "where is everyone" without coordinates, and they converge on a small number of structurally similar substitutes rather than reinventing the wheel five times. Blades in the Dark folds all spatial/tactical stakes (outnumbered, no cover, a choke point, a vantage point) directly into its Position axis (Controlled/Risky/Desperate) and Effect axis (Limited/Standard/Great), both set by the GM purely from fictional description at the moment of the roll, with no distance or coordinate input anywhere in the mechanic ([Blades in the Dark: Setting Position & Effect](https://bladesinthedark.com/setting-position-effect)); the one quasi-spatial tool it does use, for chases and cornering specifically, is a pair of opposed progress clocks racing against each other, not a position-tracking system ([Fictional Positioning when Forging in the Dark](https://offguardgames.com/2019/07/08/fictional-positioning-in-fitd/)). Fate Core sits one notch more concrete: scenes use a small number of abstract zones (2-4 typical, "more than six or so tends to get cumbersome"), melee only works within a zone, ranged attacks reach up to two zones away, and moving costs a free action for one zone or a skill roll for more — a countable adjacency unit cheaper than a grid but more concrete than pure narration ([Zones in FATE CORE](https://www.worldanvil.com/w/fate-core-moose2181/a/zones-article); [Fate Core: Movement](https://fate-srd.com/fate-core/movement)). Ironsworn collapses the same question to its simplest form: Strike is rolled with a different stat depending only on whether the fictional situation is "close quarters" or "at range," and Enter the Fray sets who holds initiative based purely on the fictional approach (face-off, sneak, ambush) — position becomes a discrete binary chosen per move rather than anything tracked continuously ([Ironsworn RPG Wiki: Strike](https://ironsworn-rpg.fandom.com/wiki/Strike); [Ironsworn Moves wiki](https://dirty20gaming-plays-ironsworn.fandom.com/wiki/Ironsworn_Moves_(gameplay))). Mörk Borg is the simplest fallback of all: flanking or high ground is worth a flat +3 or -3 modifier to the roll, nothing more, and reviewers explicitly praise this abstraction as suited to "the current trend of online play" — i.e., theater-of-the-mind is treated as a feature for remote/text play specifically, not a compromise ([Welcome to the Deathtrap: Game Review: Mörk Borg](https://deathtrap-games.blogspot.com/2022/09/game-review-mork-borg.html)).

The one directly relevant empirical finding about an actual LLM attempting this, rather than a human GM, is a cautionary tale worth taking seriously: a published research system (ChatRPG) initially gave its narrating model no spatial reasoning structure at all, and "unless participants meticulously described their actions, v1 often resulted in non-sensical outcomes, such as characters stumbling or self-injuring when the system failed to identify an appropriate target" — one participant's simple kick was narrated as an unjustified self-inflicted trip ([Static Vs. Agentic Game Master AI for Facilitating Solo Role-Playing Games, arXiv 2502.19519v2](https://arxiv.org/html/2502.19519v2)). The fix the paper's authors converged on was *not* to add spatial state tracking or a grid — it was to move combat resolution into a structured "Battle tool" that takes hit-chance and damage-severity parameters directly as tool-call arguments, sidestepping positional reasoning rather than solving it, while leaving prose narration itself unconstrained. This is a strong, if narrow, empirical confirmation that an LLM narrating combat with zero structured backstop breaks down in practice, not just in theory — and that the fix is a structured tool boundary, matching this project's own already-adopted P13 three-layer architecture (deterministic tool-calls own hard mechanics; the LLM narrates), rather than either a visual grid (the path one commercial competitor, Friends & Fables, took by reintroducing hex battlemaps and token movement) or fully unconstrained prose (the path that failed for ChatRPG v1).

## What this pass changes in the constitution

Pattern P5 is explicitly flagged in the constitution as "not settled" and "warrant[ing] dedicated design work, not a quick decision" — this research does not claim to close that flag, but it gives P5 something it has lacked since it was written: two concrete, differently-shaped candidate mechanisms, one per stated flavor, each grounded in real shipped systems rather than invented from scratch, plus a genuine, named gap (the hybrid-merge tie-break rule) that no source in either genre has solved and that any adopting spec must treat as original work. The recommended amendment keeps P5's status as "open" (consistent with the constitution's own instruction not to rush this decision) while attaching the two candidate mechanisms as the leading options a future `/speckit-plan` should evaluate against, and extends Pattern P6's already-adopted priority-tag companion mechanism to explicitly cover acquired, slot-claiming abilities (not just projectile modifiers), since this round found the identical primitive independently reinvented in a different genre (Isaac) for a structurally identical problem.

Two smaller findings are worth recording even though they don't yet warrant a constitution edit. First, the "identity layer separate from magnitude layer, composed by slot reservation rather than competition" pattern that Diablo III's Legendary Powers demonstrate is a clean structural precedent for how P5's eventual mechanism should coexist with this project's ordinary numeric-stat progression — the acquired, source-derived ability should occupy its own reserved slot rather than rolling against a character's regular stat growth, avoiding a crowding-out failure mode none of this project's existing patterns currently name. Second, on the spatial/tactical side-question: no constitution pattern currently addresses positional combat resolution at all, and this research recommends the project adopt a discrete relationship-state (engaged-in-melee / at-range / flanked / cornered), living in P13's externalized tool-call/state-store layer and resolved via P8's deterministic degree-of-success, as a lightweight companion to the existing architecture rather than a new numbered principle — the ChatRPG finding that ungrounded LLM spatial narration produces incoherent outcomes is itself the strongest argument for keeping this state in the deterministic layer P13 already mandates, not for adding a visual grid.

## Conclusion

The deepest continuity across this round's two research notes is that every genre examined independently rediscovered the same fix for "how do you generate variety without either an unmanageable table or an ungoverned free-for-all": **push the combinatorial burden onto a small, fixed set of categorical gates (source tags, manufacturer identity, god-pairs, playstyle axes) and let a separate, simpler mechanism (a weighted roll, a cumulative counter, a priority rank) resolve everything within the gate** — never one undifferentiated system trying to do both jobs at once. Diablo, Path of Exile, and Borderlands converge on this for items; Hades and Delve converge on the identical shape (key the special-case table off a low-cardinality dimension) for entirely different genres and different problems, which is stronger evidence for the pattern's generality than any single case could provide alone. What remains genuinely unsolved — and should stay flagged as such rather than papered over — is the exact tie-break rule for mixed/hybrid histories: every LitRPG series that addresses hybrid classes at all reaches for a named-merge solution, but not one of them states the numeric trigger for when a merge fires instead of a single winner, meaning this project's eventual P5 implementation will need to author that one piece from scratch rather than import it. On the spatial side-question, the clearest takeaway is negative but useful: no narrative TTRPG and no LLM-GM research project found a way to make *fully* unstructured prose safe for tactical combat — every system converges on some minimal discrete state (a position axis, a zone count, a close/range binary, a battle-tool schema), which should settle this project's own remaining uncertainty in favor of a lightweight relationship-state living inside the already-adopted P13 architecture, not a debate between "grid" and "pure narration" as the only two options.
