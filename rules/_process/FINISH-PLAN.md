  expect to use it. Ch.13 stays as an optional, unmaintained example module. Rules must never depend
  on it.
  - Playtests use a world generated by the world-seed procedure (I-028), not the Vale.

    I-025.

  work needing large reads of the 500k-word corpus. The orchestrator does small fixes itself.
- **Quality bar, verbatim:** "holy shit, that's done." Concretely:
  - No dangling threads.
  - No workarounds where the real fix exists.
  - No "table this for later" when the permanent fix is within reach.
  - Everything documented.
  - Search before building.
  - Ship finished things, not plans.
- **Standing goals:** player freedom to try anything, and AI correctness. Player-facing complexity
  is NOT a constraint.

## Standards every agent follows
- **Read first:**
  - `_process/BRIEF.md` (§10 chapter format, §11 decision-log format, §12 data conventions,
    Addenda A and B);
  - `_process/AUTHOR-BRIEF.md`;
  - the ledger rows you own;
  - only the chapter sections you need. Use grep and section reads; the corpus is 500k words.
- **Edits:**
  - Make every edit an exact, unique-match replacement, scripted from the scratchpad with
    `assert count == 1`.
  - Tag each edit `[revision: I-NNN]` (Verification uses `[verification: …]`).
  - Record each decision as a DL entry in the owning chapter's fragment
    `appendix/fragments/DL-CC.md`, then re-assemble `appendix/decision-log.md` and
    `appendix/traceability.md` the way the integration agent did (see
    `_process/integration-report.md`).
- **Data:**
  - Keep YAML parse-valid.
  - Every new id must be registered in the owning file's block, with tags in `tags.yaml`.
  - Recompile `data/anchors.yaml` with `_process/simulation/12-compile_anchors.py` when cards
    change.
- **Generated data:** many data files are produced by `_process/simulation/*gen*` scripts. When you
  change generated content, change the generator too, re-run it and confirm the output equals your
  edit, so a future re-run never silently reverts the fix.
- **Numbers:**
  - Any balance claim is backed by a deterministic, seeded sim script in `_process/simulation/`,
    with its output file committed next to it.
  - Tables in chapters quote those outputs.
- **Exit check:** `python _process/validate_ruleset.py` must end at 0 ERROR / 0 WARN.
- **Ledger:** update `_process/issue-ledger.md` for every row touched (status and resolution with
  evidence). Open new rows for anything found and not fixed, with the reason.
- **Report:** keep a running report at `_process/reports/<wave>-report.md`, appended after every
  step.
- **Git:** never commit or push. The orchestrator does.
