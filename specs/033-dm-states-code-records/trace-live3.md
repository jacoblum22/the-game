## 1. CRASH (073512, game inputs 30-39; 9 of 9 commits on the search offer failed)
- **Exception:** `AttributeError: 'str' object has no attribute 'get'`, `engine/resolve/costs.py:280` in `_apply` (cost.time branch). Full traceback in `fighter1.log:30-76`, repeated per retry. The save keeps only `game_inputs.outcome` (no traceback, no event, no turn row for a failed input).
- **Line:** `row = (rules.resolution["time_cost"].get(mode) or {}).get(sev)`. For `mode == "conflict"` the table value is the string `"listening clock only"` (`rules/data/resolution.yaml:240`). It is truthy, so `or {}` does not rescue it. The `isinstance(row, Mapping)` guard on the next line (-> `CostRefused`, which `pipeline._consequence:1075` turns into "try the next cost") is never reached. The line dates from feature 004; no test hits it.
- **Trigger state:** a fight began at seq 532 (turn.8, `conflict` meta; mode `conflict`) and never ended. The PC walked away, but Nedmund stayed `engaged`. At input 29 (turn.13, seq 636-640) the DM called `propose_roll` verb.observe `stakes:"risky" fail_cost:"cost.time"` (call.turn.13.dm.0.0). The player chose go big (seq 641-643, dire). On commit the roll failed or was a near-miss, so `cost.time` was due, no clock listened to it, and the code went to the `advance_time` row.
- **Repeatable:** yes. `Game.replay` of the copied save raises the identical error at input 30. The rng is seeded, so the same roll comes up on every retry. Only `withdraw` or `/fix` escaped it (inputs 40-41).
- **Why `cost.time` was legal in conflict (rule 01.13.5: "False in conflict mode unless a listening clock exists").** `check_cost_decl` saw `stakes_source=listening_clock` (spied: `src=listening_clock -> None`). `established_stakes_sources` (`costs.py:123`) admits `listening_clock` when ANY active clock exists, not one listening for `cost.time`. The world's faction-goal clocks (seq 179-184) always qualify. `structural_fit` (`costs.py:85`) then trusts the source name. `dm_tools.propose` (`dm_tools.py:958-966`, `verb_costs` puts `cost.time` first for Observe) picked that source. No check reads the mode.
- **Class:** code bug (the `costs.py:280` crash), plus a low-precision check (`costs.py:123/85`). The model's choice (`fail_cost:cost.time`) was legal by the rules it was given and not the cause. The fight never ending is a separate model/design matter (nothing ended the conflict; the DM has no obvious end tool in the packet).
- **Fix candidates:** (a) minimal: `row = tc.get(mode); row = row.get(sev) if isinstance(row, Mapping) else None`, so the existing `CostRefused` and fallback to the alternate cost (cost.exposure) work. (b) at `costs.py:123`, count `listening_clock` only if some active clock lists `cost.time` or `cost.exposure` (`_listening_clocks`). (c) in `structural_fit`, `cost.time` is false in conflict without a clock (matches 01.13.5). (d) add a test: observe roll, failure, `mode=conflict`, no clock. (e) a way to answer "something went wrong" other than retrying (the retry loop was identical 9 times).

## 2. LEAKED LINE (073517, game input 20 / turn.4 seq 461-466; again input 38 / turn.22)
- **Call:** call.turn.2.dm.0.0, `propose_roll` {verb.handle, target "the leather satchel", `as:"thing"`, `change_kind:"take"`, `change_what:"the satchel"`}. No `new_item` and no id: the satchel existed only in prose. `_party` (`dm_tools.py:651`) returns a `thing` as written and makes no entity. In `_roll` (`dm_tools.py:737-748`) `change_what` is not equal to `target`, so `what=_id(...)` is the bare string, not in `st.entities`, giving `Change(kind="take", what=None, description="the satchel")`.
- **Line:** `change.py:321-323`: `what is None` -> `ChangeResult(refused="nothing on record by that name to take")`. This copies to `entry.change_refused` (`pipeline.py:980`), then `oof.change_result_line` (`oof.py:681-682`) -> `Not applied: ...` inside `[RESULT]`. Only `open`/`close` have a `description` fallback (`_described`); `take` and `give` have none.
- **Not a leak:** one OOF block feeds both the player's screen and the DM's packet ("WHAT JUST HAPPENED", call.turn.4.dm.0.0 line ~104). `oof.py:680` says the line is meant for the player, "so 12.3.6 can explain it". Nothing filters it. The DM saw it, then correctly made the item with `change new_item` in the same turn (seq 489-490, call.turn.4.dm.0.0), so the end state was right and only the line was wrong.
- **Frequency:** 2 of 2 take-rolls on a thing not yet an entity (turn.4 "the satchel"; turn.22 "the folded letter", item created seq 779 after the roll, call.turn.20.dm.0.0). 0 hits in the other 12 dm-tools saves.
- **Class:** design gap (a thing named in words is never made before the roll) plus internal wording shown to the player. The model's choice is reasonable: the tool text says "something not on record may be named in words".
- **Fix candidates:** (a) `take` with a described thing: make the item (as `open` uses `_described`) or take it unrecorded, with no refusal. (b) the "Not applied" text in plain words (e.g. "the game has no record of that yet") or hidden from the player when the DM can fix it in the same turn. (c) the prompt: `new_item` before the roll for a thing the roll takes. (a) removes the cause; (b) only hides it.
